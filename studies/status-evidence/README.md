# Errors cannot disappear through an unreadable status

A captured failed tool span used OTLP status code `2`. Changing only its JSON
representation to the reference-decoder-supported string `"2"` made TraceLens
call it `UNSET`, report no errors or retries, and show a 100% error reduction
against the unchanged trace. No warning explained the lost failure. An unfamiliar
code or malformed declaration produced the same misleading comparison.

The source decoder now preserves exact known codes and retains unrecognized
status data as `UNKNOWN`. Summary error counts remain known subtotals, with an
additional missing-outcome count. Comparison error deltas/percentages are null
when any contributing status is unknown. Call counts and elapsed/self time still
use their independently recorded evidence. An eligible later tool repetition
with an unreadable preceding status has an unknown possible-retry outcome.

| Declaration | Previous failed-span interpretation | Current interpretation |
| --- | --- | --- |
| `2`, `STATUS_CODE_ERROR` | ERROR | ERROR |
| `"2"`, `"02"`, `"+2"`, `" 2 "` | UNSET | ERROR |
| Future integer `3`, invalid name/shape | UNSET | UNKNOWN; raw field retained |
| Fraction `2.5`, boolean `false` | UNSET | UNKNOWN; no numeric coercion |
| `ERRORSTATUS_CODE_` | ERROR | UNKNOWN; no substring enum matching |
| Missing/null/empty status; missing/null code | UNSET | UNSET; legitimate default |
| Known code with non-text message | Known code, invented message text | Known code; raw field and warning |

Jaeger uses the same outcome rule for status tags. Duplicate code/error tags
do not choose a winner. A valid independent ERROR or `error=true` can still
record failure when a different tag is unreadable; the warning and original
tags explain that fallback. Existing valid lowercase aliases and legacy boolean
error flags remain supported. Optional status-description damage does not erase
an independently known code.

## Independent capture and limits

`capture.py` pins OpenTelemetry SDK/exporter 1.45.1 and Protobuf 7.36.2. It raises
and catches a controlled local RuntimeError, records the exception and ERROR
status, and follows it with a successful same-parent tool call. The three native
SDK spans, their pre-serialization outcomes and exporter output are retained.
No model, remote service or collector is called. Exception stack text is explicitly
path-free. Timing and identities are generated by the SDK.

Labelled variants replace only the failed span's status code. The independent
Protobuf `ParseDict` runs before identities are converted from base64 to the
viewer-compatible complete hex spelling. `fixtures/oracle.json` retains package
versions, driver hash, source status observations and each decoder result.
`native-jaeger.json` is a conversion by the existing `scripts/otlp-to-jaeger.mjs`,
not a capture from a running Jaeger server. Other Jaeger/shape cases are explicitly
constructed controls, not claimed production incidents.

[ProtoJSON](https://protobuf.dev/programming-guides/json/) describes enum names,
integer encodings and unset null fields. The pinned Python decoder also accepts
quoted integers. It additionally coerces numeric `2.5` to `2` and `false` to `0`;
the viewer deliberately refuses those lossy coercions. This is a focused evidence
study, not comprehensive ProtoJSON conformance certification. UNSET is the protocol
default; it does not prove a successful request or complete instrumentation.

`StatusCode` adds `UNKNOWN`; comparison `CallEvidence.error` can now be null.
Direct core consumers must handle that outcome. `unknownStatusCount` and
`unknownRetryCount` are optional summary fields present only when nonzero, so
ordinary summaries keep their existing shape. Status `raw` is retained for unknown
or damaged fields. Complete known-code controls keep their exact console/report
output. Independently detected incomplete span inventory also qualifies summary
error/retry headlines instead of asserting complete zero counts.

## Reproduce

```sh
npm ci
npm run build
node studies/status-evidence/replay.mjs --out studies/status-evidence/cache/full.json
node studies/status-evidence/retain.mjs studies/status-evidence/cache/full.json studies/status-evidence/results/after.json
```

Replay supports `--cli PATH --node PATH --out PATH --observe-only` for a baseline
or installed local package. It checks 39 native, encoding, shape/default and Jaeger
cases through the core API and four actual console commands per case: comparison
JSON/text, summary and tree. `results/before.json` and `after.json` retain all
statuses, warnings, summaries and captures. Identical full reports are stored once
under SHA-256 references. Comparison JSON stdout reconstructs exactly as
`JSON.stringify(reports[stdoutReportRef], null, 2) + '\n'`; its raw hash is checked
before retention. Other stdout/stderr is unedited.

Regenerate a new independent capture in a separate directory:

```sh
uv run studies/status-evidence/capture.py --output /tmp/tracelens-status-new
node scripts/otlp-to-jaeger.mjs /tmp/tracelens-status-new/native-integers.json > /tmp/tracelens-status-new/native-jaeger.json
```

Browser replay accepts completed before/after production-build directories:

```sh
node studies/status-evidence/browser.mjs BEFORE_DIST AFTER_DIST OUTPUT_DIRECTORY
```

Each Chromium/Firefox context loads the empty app and local fonts, disconnects
and stops the server **before its first trace import**. It compares three status
variants, downloads each full report, inspects the candidate's failed span,
downloads its JSON, and checks the visible error/retry states. Page/policy errors,
external/late requests, accessibility violations and document overflow are checked.
Served, browser-received and on-disk build assets must have identical hashes.
Screenshots are written to `docs/assets/status-evidence`.

## Recorded results

Baseline `b7773d699ec3590c81bd455f87a2d36581e53ce2` was built from its original
archive. The corrected source replay has zero disagreements in 39 cases versus
26 in that baseline. All 13 already-correct cases retain identical reports and
console captures (52 commands). Offline Chromium/Firefox at 1440 and 375 px
produced 12 misleading comparisons before and zero after, across 24 actual
comparison downloads. Eight additional selected-span downloads retain the
before/after status and raw data. Each view loaded the same 24 files served by
its corresponding tested build. All 16 screenshots were visually inspected:
the mobile table wraps the missing-count text; summary and raw-status text stay
readable within the existing layout.
